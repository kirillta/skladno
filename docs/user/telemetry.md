# Diagnostic and usage data

Skladno’s packaged Windows app can send a small set of pseudonymous reliability and usage events to PostHog during the public beta. It is enabled by default to help improve app reliability and editorial workflows. You can turn it off at any time. Enabling it creates a random installation identifier stored only in Electron’s runtime settings, outside the Article database, backups, and restore staging. Disabling it stops future collection, clears queued events and that identifier, and creates a new identifier if it is enabled again. Previously delivered events cannot be recalled by the switch.

The allowlisted events are process starts, completed/failed/cancelled AI operations, explicit Proposal reviews, aggregated Draft checkpoints, backup/recovery outcomes, and safe application-failure categories. Event-specific fields are finite enums, non-negative counters, or bounded millisecond durations. Every event also has schema version, application version, platform, architecture, and timestamp. It never includes Article or Revision identifiers, titles, Article text, prompts, AI responses, API keys, environment values, paths, URLs, raw errors, or request/response bodies.

Skladno uses one US (Virginia) PostHog Cloud project. It is configured to discard IP addresses and retains events for 14 days. Only the project owner has access. Automated tests and development builds never send events to PostHog. To request deletion, copy your Telemetry ID from Settings, email it to [kirill.taran@hotmail.com](mailto:kirill.taran@hotmail.com), then turn telemetry off. Turning it off clears that ID locally, so copy it first. The project owner deletes the matching pseudonymous PostHog person and confirms completion by email. This preview has no production configuration enabled, so no telemetry is delivered.
